# FT61E0A5 notes (no datasheet in hand)

Facts below come from the stock PS10 1.0.5 image unless marked otherwise.
Confirmed means: the stock firmware, run in `tools/emu.py` with this register
model, behaves like the real device (answers `tuya:` init, product info
`{"p":"o9a6at9cyfchb47y","v":"1.0.5","m":1}`, datapoint reports, and the `0x0A`
EEPROM-clear-and-reset).

## Core
- PIC16F1 enhanced mid-range instruction set, **opcode bits 13:12 rotated**:
  FMD = (PIC + 1) mod 4 (`tools/fmd.py`). gputils assembles/disassembles it as
  `p16f1829` once converted. Erased = 0x3FFF in both.
- 10K × 14 program flash (0x0000-0x27FF), 128 B data EEPROM, 1 KB RAM.
- Core registers, banking (`movlb`), FSR linear/program-memory windows
  (FSR ≥ 0x8000 reads program memory) and `INTCON` (GIE bit 7, PEIE bit 6) are
  PIC16F1. Confirmed.
- The interrupt stub at 0x0004 in the image saves context into the shadow
  registers by hand, and the application's ISR at 0x604 ends with `retfie`.

## Memory map of the update image
- 0x000-0x5FF: bootloader (resident, not in the image; the image has an
  interrupt stub and `nop`s there, which the bootloader doesn't write).
- 0x600 reset, 0x604 interrupt: application.
- No header, checksum or signature.

## Bootloader contract (what an application must do)
- Link at 0x600, never write below it.
- On Tuya `0x0A`: write `0xFF` to data EEPROM 0x00 and 0x01, then `RESET`.
  The bootloader answers the module's retried `0x0A` and takes the `0x0B`
  packets (256-byte, 4-byte offsets, frame version 3 from the stock
  bootloader). Check for `0x0A` early in the UART loop and keep the watchdog
  running, so an update can always get in.
- Answer Tuya at 9600 8N1 on the hardware UART.
