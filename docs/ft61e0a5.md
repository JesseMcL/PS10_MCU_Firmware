# FT61E0A5 notes

Source: **FT61E0Ax / FT64E0Ax datasheet V1.02** ([datasheets/](datasheets/)),
checked against the stock PS10 1.0.5 image. "Emulated" means the stock image,
run in `tools/emu.py` with this register model, behaves like the real device:
it answers `tuya:` init, gives product info `{"p":"o9a6at9cyfchb47y","v":"1.0.5","m":1}`,
reports datapoints, and on `0x0A` clears EEPROM 0/1 and resets.

## Core
- 49 instructions, the PIC16F1 (enhanced mid-range) set under FMD mnemonics
  (`LDWI`=`movlw`, `STR`=`movwf`, `BSR`/`BCR`=`bsf`/`bcf`, `LJUMP`/`LCALL`=`goto`/`call`,
  `RETW`=`retlw` ...). The datasheet gives no encodings. In the image, **opcode
  bits 13:12 are rotated**: FMD = (PIC + 1) mod 4 (`tools/fmd.py`). gputils
  assembles and disassembles it as `p16f1829` after conversion. Erased = 0x3FFF.
- Instruction clock: 1T, 2T or 4T of SysClk (BOOT-level `TSEL`, default 2T).
  SysClk = 16 MHz HIRC here (`OSCCON` = 0x71).
- 16-level hardware stack; stack over/underflow reset (`STVREN`, default on).
- Core registers in every bank: `INDF0/1`, `PCL`, `STATUS`, `FSR0/1`, `BSREG`,
  `WREG`, `PCLATH`, and `INTCON` = GIE, PEIE, EEIE, LVDIE, OSFIE, EEIF, LVDIF,
  OSFIF. That last one differs from PIC16F1 below bit 6: bit 2 is the EEPROM write
  flag (the stock EEPROM write clears it first).
- Banks 0-12 and 31; GPR 0x20-0x6F per bank, 0x70-0x7F common.
  FSR 0x2000-0x29AF = linear RAM, FSR ≥ 0x8000 = program memory (low byte).

## Memory
- Program PROM 10K × 14 (0x0000-0x27FF; 160 pages × 64 words); addresses
  above 0x27FF wrap to 0. Self-programmable (IAP): page erase, word write; the
  CPU stalls ~1 ms per operation.
- Data EEPROM 128 × 8 (0x00-0x7F), self-timed writes (3-5 ms).
- RAM 1K.
- **UCFG** (BOOT-level configuration: oscillator, WDT, LVR, read protection,
  `TSEL`...): read with `EECON1.CFGS = 1` from 0x8000; unimplemented addresses
  read undefined. Software can never write or erase UCFG.
- **Protection:** `CPB` (whole array) blocks only the serial programming port.
  Software can always read the PROM and EEPROM "regardless of the value of CPB".
  `FSECPB0-9` (1K sectors) block software reads of the protected sector
  (EEDAT keeps its old value). So a dump of the bootloader works unless
  sector 0 is protected, and then it returns repeated values instead.

## Registers this project uses
| Address | Name | Use / stock value |
|---|---|---|
| 0x099 | `OSCCON` | `0x71`: MCKCF 0111 (÷1), SCS = 1 (HIRC) → SysClk 16 MHz |
| 0x09A | `PCKEN` | bit 0 ADC, 1 TIM1, 2 TIM2, 3 TIM4, 4 SPI, 5 USART1, 6 I2C, 7 USART2 |
| 0x097 | `WDTCON` | `0x55`: WDTPRE ÷4, WDTPS 32768, SWDTEN → ~4 s on LIRC 32 kHz |
| 0x19D | `MISC0` | WCKSEL = 00 (WDT on LIRC); the datasheet also lists it at 0x11C |
| 0x191-0x196 | `EEADRL/H`, `EEDATL/H`, `EECON1`, `EECON2` | EECON1: EEPGD 7, CFGS 6, FREE 4, WRERR 3, WREN 2, WR 1, RD 0. Read: PROM/UCFG data valid **2** instruction cycles after RD, DATA EEPROM after **4** |
| 0x48C | `UR1DATAL` | USART1 data |
| 0x48E | `UR1IER` | `0x23`: TCEN, TE, RXNE interrupt enables |
| 0x48F | `UR1LCR` | `0x01`: 8 bits, no parity, 1 stop |
| 0x491 | `UR1MCR` | `0x18`: TXEN, RXEN (pins switch to the UART automatically) |
| 0x492 | `UR1LSR` | bit 0 RXNEF, 1 OVERF, 3 FEF, 5 TXEF (empty), 6 IDLEF |
| 0x494/0x495 | `UR1DLL/DLH` | `0x0068` → 16 MHz / (16 × 104) = **9615 baud** |
| 0x49C | `UR1TC` | bit 0 TCF (write 1 to clear) |
| 0x19E / 0x19F | `AFP0` / `AFP1` | USART1 TX / RX pin: reset 00 = **PA6 / PA7** (stock doesn't change them) |
| 0x21F | `ODCON0` | bit 0 `UR1OD`: USART1 TX open drain (stock sets it) |

## Memory map of the update image
- 0x000-0x5FF: bootloader (resident on the chip; the image has an interrupt stub
  and `nop`s there, which the bootloader discards).
- 0x600 reset, 0x604 interrupt: application. No header, checksum or signature.

## Bootloader
See [bootloader.md](bootloader.md): CRC-16 check of the application at boot
(stored in EEPROM 0x00/0x01), Tuya updater at 9600, never overwrites itself.

## Bootloader contract (what an application must do)
- Link at 0x600, never write below it.
- On Tuya `0x0A`: write `0xFF` to data EEPROM 0x00 and 0x01, then `RESET`.
  The bootloader answers the module's retried `0x0A` and takes the `0x0B`
  packets (256-byte, 4-byte offsets, frame version 3). Check for `0x0A` early
  in the UART loop and keep the watchdog running, so an update can always get in.
- Answer Tuya at 9600 8N1 on USART1 (PA6/PA7).

## Recovery
ICSP uses ISPCLK = PA2 (pin 14) and ISPDAT = PB6 (pin 4), the triac and LED
lines. DCProgrammer 0.9.8.3 lists the FT61E0Ax (10240 words, 128 B EEPROM).
